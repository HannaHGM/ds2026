# 3.3 Lab: clean your own data

Everything from 3.1 and 3.2, on the dataset you will be assessed on.

Work in `project/cleaning.ipynb`. Your data file stays in `data/`, which is never pushed, so
the notebook is the record of what you did: anyone reading it should be able to get from the
raw file to your clean one without asking you a question.

**Commit after every step.** Twelve small commits with readable messages beat one commit
called "cleaning". They are also the evidence that this was your work, which matters in Week
10.

```bash
git add project/cleaning.ipynb
git commit -m "..."
git push
```

---

## 1. Load it and look

Shape, `dtypes`, `head()`, and the number of missing values per column. Write one markdown
cell saying what one row of this dataset represents.

> `git commit -m "Load project data and describe one row"`

## 2. One row per thing

Exact duplicate rows, and duplicated identifiers if you have an id column. Decide whether a
repeat is an error or a real second observation, and say which.

> `git commit -m "Check for duplicate rows"`

## 3. Map the missing values

A count and a percentage per column. Pick the three worst and write one sentence each on what
a blank means in that column.

> `git commit -m "Map missing values by column"`

## 4. Values that are not values

Refusal codes (999, -1), empty boxes stored as 0, impossible dates, negative quantities, ages
of 3. Turn them into `NaN` and say why each one is not an outlier.

> `git commit -m "Convert refusal codes and impossible values to NaN"`

## 5. Columns stored as the wrong type

Numbers that arrived as text, dates as strings, categories as numbers. Convert them, then
check what your conversion silently turned into `NaN`.

> `git commit -m "Parse numeric and date columns"`

## 6. Why is it missing

For your two worst columns, argue MCAR, MAR or MNAR. For MAR, show the evidence: the missing
rate broken down by another column. For MNAR, say plainly that you cannot prove it from the
data and give the reason you believe it anyway.

> `git commit -m "Classify missingness mechanisms"`

## 7. Decide what to do about it

Per column: drop, fill with a constant, fill by group, or model. Apply it, and add a boolean
column recording which rows you filled.

> `git commit -m "Impute missing values and flag imputed rows"`

## 8. Tidy the categories

Collapse spellings of the same answer, keep "prefer not to say" as its own category, order the
ordinal ones explicitly, and group rare categories if one column has a long tail.

> `git commit -m "Tidy and order categorical columns"`

## 9. Look at the shape

Histogram and skew for each numeric column. Apply the IQR rule, then overrule it where the
extreme values are real. Say what you kept and why.

> `git commit -m "Check distributions and outliers"`

## 10. Transform, if the analysis needs it

Log or power-transform the badly skewed columns, scale if you will use a distance-based
method later. Keep the original column alongside the transformed one, and note which you will
report in.

> `git commit -m "Add transformed columns"`

## 11. Build the variables you actually want

Composites, ratios, differences, scale scores. Check every ratio for zero denominators and
infinities before you trust it.

> `git commit -m "Derive analysis variables"`

## 12. Save, and write it up

Save the clean table to `data/` (not committed), then write the cleaning section of
`project/README.md`: what you removed, what you filled and how, what you transformed, and the
decision you are least sure about.

> `git commit -m "Write up cleaning decisions in README"`
